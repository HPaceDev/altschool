# Портал согласования

Рабочая площадка проекта на этапе проектирования: кликабельный прототип, вопросы
к заказчику с ответами прямо на сайте, журнал решений, границы работ и растущее
техническое задание — в одном месте, по одной ссылке.

Ключевое свойство: **история не переписывается**. Ответы версионируются,
утверждения фиксируются вместе с автором, временем и текстом, а журнал событий
защищён от изменения и удаления на уровне PostgreSQL, а не только в интерфейсе.

## Что внутри

| Вкладка | Содержание |
|---|---|
| Обзор | Что сейчас нужно от заказчика, состояние проекта, последние события |
| Прототип | Текущая и прошлые версии прототипа, карта экранов с состояниями |
| Вопросы | Вопросы, ответы, версии ответов, обсуждение, утверждение |
| Решения | Принятые решения с контекстом и последствиями |
| Скоуп | Что входит в этап и, отдельно, что сознательно не входит |
| Риски | Риски и что мы с ними делаем |
| Глоссарий | Общий словарь проекта |
| ТЗ | Требования с критериями приёмки и ссылками на вопросы-основания |
| Приёмка | Правила приёмки и чек-лист критериев |
| Журнал | Полная хронология: кто, что и когда сделал |

## Как устроена защита истории

Три уровня, от слабого к сильному:

1. **Интерфейс.** Правка ответа создаёт новую версию, прежняя остаётся видимой.
   Вопросы не удаляются, а получают статус «снят» с указанием причины.
2. **Приложение.** Каждое действие, меняющее состояние, пишет запись в
   `audit_log`. Утверждение дополнительно сохраняет текст, который человек видел
   перед нажатием кнопки, вместе с его IP и браузером.
3. **База данных.** Триггеры в миграциях `0001` и `0002` отклоняют `UPDATE`,
   `DELETE` и `TRUNCATE` для таблиц `audit_log`, `answers`, `approvals` и
   `comments`. Даже прямое подключение к базе правами приложения не перепишет
   ответ задним числом — сервер откажет.

Обойти третий уровень можно только правами владельца схемы (`DROP TABLE`), см.
раздел «Роль приложения».

## Локальный запуск

Нужны Node.js 22+ и PostgreSQL 16+.

```bash
npm install
cp .env.example .env.local          # укажите DATABASE_URL, AUTH_SECRET, OWNER_EMAIL
npm run db:migrate
npm run db:seed
npm run dev
```

`AUTH_SECRET` сгенерировать: `openssl rand -hex 32`.

Откройте http://localhost:3000, введите адрес из `OWNER_EMAIL`. Пока почтовый
сервис не подключён, ссылка для входа показывается прямо на странице и дублируется
в консоль сервера — портал полностью работоспособен без почты.

### Полезные команды

```bash
npm run db:generate   # создать миграцию по изменениям в схеме
npm run db:migrate    # применить миграции
npm run db:seed       # наполнить портал стартовыми данными
npm run db:reset      # пересоздать базу с нуля (только для разработки)
npm run db:studio     # веб-интерфейс к базе
npm run typecheck     # проверка типов
node e2e/portal.mjs   # сквозной прогон в браузере (нужен запущенный npm run dev)
```

`db:reset` пересоздаёт схему целиком: очистить таблицы с историей иначе нельзя,
и это ровно то поведение, которого мы добивались.

## Развёртывание

Два пути на выбор. Первый не требует своего сервера и делается в браузере,
второй — если инфраструктура должна остаться у вас.

## Вариант А: Vercel + Supabase

### 1. База данных (Supabase)

1. Создайте проект на [supabase.com](https://supabase.com) — бесплатного тарифа
   хватает с запасом. Регион выбирайте ближе к пользователям; если в системе
   будут персональные данные граждан РФ, разместите базу у российского провайдера
   (Yandex Cloud, Selectel) — Supabase в этом случае не подходит.
2. **Project Settings → Database → Connection string → URI**, режим **Session
   pooler** (адрес вида `aws-0-<регион>.pooler.supabase.com`).

   Именно пулер, а не прямое подключение к `db.<проект>.supabase.co`: прямой
   адрес отвечает только по IPv6, которого у Vercel нет, и приложение молча
   не достучится до базы.

3. Подставьте пароль проекта вместо `[YOUR-PASSWORD]` — это `DATABASE_URL`.
   Если в пароле есть `@`, `:`, `/` или `#`, закодируйте их (`@` → `%40`).
4. Создайте структуру: **SQL Editor → New query**, вставьте целиком
   [`drizzle/bootstrap.sql`](drizzle/bootstrap.sql) и нажмите **Run**.

   Один файл создаёт таблицы, триггеры неизменяемости, отметки о применённых
   миграциях и стартовое наполнение — 14 вопросов первого круга, словарь
   процесса и типовые риски. Ни терминал, ни Node.js для этого не нужны.

   Если предпочитаете командную строку, тот же результат даёт
   `DATABASE_URL='…' npx drizzle-kit migrate && npm run db:seed`.

Драйвер настроен с `prepare: false`, поэтому работает и через пулер Supabase.

### 2. Приложение (Vercel)

1. Импортируйте репозиторий на [vercel.com](https://vercel.com).
2. Задайте переменные окружения:

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | строка подключения из Supabase |
   | `AUTH_SECRET` | `openssl rand -hex 32` |
   | `APP_URL` | адрес портала, например `https://portal.вашдомен.ru` |
   | `OWNER_EMAIL` | ваша рабочая почта |
   | `RESEND_API_KEY` | ключ [Resend](https://resend.com), опционально |
   | `MAIL_FROM` | адрес отправителя, например `portal@вашдомен.ru` |

   `APP_URL` можно не задавать: адрес определится из заголовков запроса. Но
   лучше задать — тогда ссылки для входа нельзя подделать через заголовок `Host`.

3. Нажмите **Deploy**. Структура базы уже создана на шаге 1, отдельно накатывать
   миграции не нужно.

4. Откройте портал и войдите под `OWNER_EMAIL` — учётная запись владельца
   создаётся при первом входе.

### 3. Доступ для заказчика

Портал закрытый: ссылку для входа получает только заведённый участник. Добавить
человека можно через `npm run db:studio` или SQL:

```sql
insert into users (email, name, role, org)
values ('ivanov@company.ru', 'Иван Иванов', 'client', 'ООО «Компания»');
```

Роли:

- `owner` — исполнитель: заводит вопросы, ведёт скоуп и ТЗ, фиксирует ответы;
- `client` — заказчик: отвечает на вопросы и утверждает ответы;
- `viewer` — наблюдатель: только чтение.

Утверждать вправе только `client` — это осознанное ограничение: подпись
исполнителя под собственным решением ничего не стоит.

### 4. Почта (опционально)

Без `RESEND_API_KEY` ссылка для входа показывается на странице и в логах сервера —
её можно отправить заказчику вручную. Для самостоятельного входа подключите
[Resend](https://resend.com): подтвердите домен, создайте ключ, задайте
`RESEND_API_KEY` и `MAIL_FROM`.

## Вариант Б: свой сервер (Docker)

Подойдёт, если данные должны оставаться на вашей инфраструктуре — например,
из-за требований к хранению персональных данных.

**Что нужно:** сервер с Ubuntu 22.04 или 24.04, минимум 2 ГБ памяти
(рекомендуется 4 ГБ) и 20 ГБ диска. Домен не обязателен.

### Без своего домена

Если домена нет, скрипт установки предложит два варианта:

- **`https://<IP>.sslip.io`** — настоящий сертификат Let's Encrypt, покупать
  ничего не нужно. sslip.io — публичный сервис, который отдаёт адрес прямо из
  имени, поэтому домен указывает на ваш сервер сам собой. Рекомендуемый
  вариант: трафик шифруется, браузер не ругается.
- **`http://<IP>`** — просто по адресу, без шифрования. Ссылки для входа и
  cookie идут открытым текстом, так что годится посмотреть самому, но не для
  показа заказчику.

В режиме по IP Caddy не поднимается вовсе, а приложение слушает 80-й порт
напрямую. Это сделано намеренно: иначе Caddy занял бы порт 443 без
сертификата, и браузер, который сам подставляет `https`, упирался бы в ошибку
TLS вместо возврата на `http`.

Переключиться на свой домен позже можно, запустив скрипт повторно: пароли
сохранятся, изменится только адрес.

### Браузер сам подставляет https

Если при заходе на `http://<IP>` адрес превращается в `https://` и страница не
открывается, причина почти всегда на стороне браузера, а не сервера.
Проверьте, откуда берётся перенаправление:

```bash
curl -I http://<IP>
```

- **`HTTP/1.1 200 OK`** — сервер отдаёт страницу, `https` подставляет браузер.
  В Chrome это «Всегда использовать безопасные соединения»
  (`chrome://settings/security`), в Firefox — «Режим только HTTPS». Отключите
  его либо добавьте исключение для адреса.
- **`301` или `308` с заголовком `Location: https://…`** — перенаправляет
  сервер. Значит портал поднят в режиме с доменом: проверьте `APP_BIND` и
  `DOMAIN` в `/opt/portal/.env` и перезапустите установщик.

Если раньше вы уже открывали этот адрес по `https`, браузер мог запомнить
требование HSTS. Сбросить: `chrome://net-internals/#hsts` → **Delete domain
security policies**.

Надёжнее же не бороться с браузером, а взять вариант с `<IP>.sslip.io` —
тогда `https` работает по-настоящему.

### Установка одной командой

Подключитесь к серверу по SSH под root и выполните:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/HPaceDev/altschool/claude/large-system-design-76o4o7/scripts/install-server.sh)
```

Скрипт спросит домен и вашу почту, после чего сам поставит Docker, заберёт
исходники, сгенерирует пароли, поднимет приложение с базой и выпустит
сертификат HTTPS. Повторный запуск безопасен: готовое переиспользуется,
пароли не перегенерируются.

На сервере с памятью меньше 3 ГБ скрипт добавит файл подкачки — сборка
Next.js требовательна к памяти и без него может прерваться.

### Или вручную

```bash
git clone -b claude/large-system-design-76o4o7 \
  https://github.com/HPaceDev/altschool.git /opt/portal
cd /opt/portal

cat > .env <<'ENV'
POSTGRES_PASSWORD=придумайте-длинный-пароль
AUTH_SECRET=вставьте-вывод-openssl-rand-hex-32
DOMAIN=portal.вашдомен.ru
APP_URL=https://portal.вашдомен.ru
OWNER_EMAIL=вы@вашдомен.ru
ENV

docker compose --profile tls up -d --build
```

База создаётся и наполняется автоматически из `drizzle/bootstrap.sql` при
первом запуске — миграции отдельно накатывать не нужно.

Профиль `tls` поднимает Caddy, который сам получает и продлевает сертификат
Let's Encrypt. Если на сервере уже настроен nginx, запускайте без профиля —
приложение будет слушать `127.0.0.1:3000`, проксируйте на него.

Порт базы наружу не публикуется: она доступна только контейнеру приложения.
Данные лежат в томе `db-data` и переживают пересборку образа, выданные
сертификаты — в томе `caddy-data`.

Обновление после изменений в коде:

```bash
cd /opt/portal && git pull && docker compose --profile tls up -d --build
```

Резервная копия базы:

```bash
cd /opt/portal && docker compose exec db pg_dump -U portal portal | gzip > backup-$(date +%F).sql.gz
```

### Роль приложения

Триггеры защищают историю от `UPDATE`, `DELETE` и `TRUNCATE`, но владелец схемы
может выполнить `DROP TABLE`. Чтобы закрыть и это, в продакшене подключайте
приложение отдельной ролью без прав DDL:

```sql
create role portal_app login password 'сложный-пароль';
grant usage on schema public to portal_app;
grant select, insert, update, delete on all tables in schema public to portal_app;
revoke update, delete on audit_log, answers, approvals, comments from portal_app;
alter default privileges in schema public
  grant select, insert, update, delete on tables to portal_app;
```

Миграции при этом накатываются владельцем схемы, а `DATABASE_URL` приложения
указывает на `portal_app`.

## Технологии

Next.js 16 (App Router, Server Actions) · React 19 · TypeScript · Tailwind CSS 4 ·
PostgreSQL · Drizzle ORM · Playwright для сквозных проверок.

Вход — одноразовые ссылки на почту: сессия в httpOnly cookie, в базе хранятся
только SHA-256 хеши токенов. Паролей в системе нет.
